# 共享记账报销小程序 - 数据库设计

## 1. 数据库概述

- **数据库类型**: MySQL 8.0
- **字符集**: utf8mb4
- **存储引擎**: InnoDB

## 3. 详细表结构

### 3.1 users - 用户表

```sql
CREATE TABLE `users` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '用户ID',
  `openid` varchar(64) DEFAULT NULL COMMENT '微信openid',
  `unionid` varchar(64) DEFAULT NULL COMMENT '微信unionid',
  `phone` varchar(20) DEFAULT NULL COMMENT '手机号',
  `nickname` varchar(50) DEFAULT NULL COMMENT '昵称',
  `avatar` varchar(255) DEFAULT NULL COMMENT '头像URL',
  `status` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '状态: 0-禁用, 1-正常',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_openid` (`openid`),
  UNIQUE KEY `uk_phone` (`phone`),
  KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='用户表';
```

**字段说明**:
- `openid`: 微信小程序用户唯一标识
- `unionid`: 微信开放平台唯一标识（跨应用）
- `phone`: 手机号，可用于手机号登录
- `status`: 用户状态，用于封禁等场景

### 3.2 ledgers - 账本表

```sql
CREATE TABLE `ledgers` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '账本ID',
  `name` varchar(50) NOT NULL COMMENT '账本名称',
  `description` varchar(200) DEFAULT NULL COMMENT '账本描述',
  `type` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '类型: 1-个人账本, 2-报销账本',
  `invite_code` varchar(10) NOT NULL COMMENT '邀请码',
  `creator_id` bigint unsigned NOT NULL COMMENT '创建者ID',
  `is_locked` tinyint unsigned NOT NULL DEFAULT '0' COMMENT '锁定状态: 0-未锁定, 1-已锁定',
  `auto_lock_days` int unsigned DEFAULT NULL COMMENT '自动锁定天数(天), NULL表示不自动锁定',
  `auto_lock_at` datetime DEFAULT NULL COMMENT '预计自动锁定时间',
  `locked_at` datetime DEFAULT NULL COMMENT '实际锁定时间',
  `locked_by` bigint unsigned DEFAULT NULL COMMENT '锁定操作人ID',
  `status` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '状态: 0-已删除, 1-正常',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_invite_code` (`invite_code`),
  KEY `idx_creator_id` (`creator_id`),
  KEY `idx_created_at` (`created_at`),
  KEY `idx_auto_lock_at` (`auto_lock_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账本表';
```

**字段说明**:
- `type`: 账本类型，1=个人账本，2=报销账本
- `invite_code`: 6位随机字母数字组合，用于邀请加入
- `creator_id`: 关联users.id
- `is_locked`: 锁定状态，锁定后任何人无法修改/删除账目
- `auto_lock_days`: 自动锁定天数，可选值：7/30/90/180/NULL(永不)
- `auto_lock_at`: 预计自动锁定时间，创建账本时根据auto_lock_days计算
- `locked_at`: 实际锁定时间（手动锁定或自动锁定时记录）
- `locked_by`: 执行锁定操作的用户ID

**自动锁定逻辑**:
1. 创建账本时，若设置了`auto_lock_days`，则`auto_lock_at = created_at + auto_lock_days天`
2. 修改`auto_lock_days`时，重新计算`auto_lock_at = updated_at + auto_lock_days天`
3. 后端定时任务每分钟检查一次，将`auto_lock_at <= now()`且`is_locked = 0`的账本设为锁定
4. 手动锁定时，`is_locked = 1`，`locked_at = now()`，`locked_by = 当前用户ID`
5. 手动解锁时，`is_locked = 0`，清空`locked_at`和`locked_by`，不重置`auto_lock_at`

### 3.3 ledger_members - 账本成员关联表

```sql
CREATE TABLE `ledger_members` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `ledger_id` bigint unsigned NOT NULL COMMENT '账本ID',
  `user_id` bigint unsigned NOT NULL COMMENT '用户ID',
  `role` tinyint unsigned NOT NULL DEFAULT '2' COMMENT '角色: 1-创建者, 2-管理员, 3-普通成员',
  `joined_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '加入时间',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_ledger_user` (`ledger_id`, `user_id`),
  KEY `idx_ledger_id` (`ledger_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_joined_at` (`joined_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账本成员关联表';
```

**字段说明**:
- `role`: 1=创建者（拥有所有权限），2=管理员（可管理成员和权限），3=普通成员
- 联合唯一索引确保一个用户在一个账本中只有一个角色
- 创建者自动拥有所有权限，不使用ledger_permissions表

### 3.4 ledger_permissions - 成员权限表

```sql
CREATE TABLE `ledger_permissions` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT 'ID',
  `ledger_id` bigint unsigned NOT NULL COMMENT '账本ID',
  `member_id` bigint unsigned NOT NULL COMMENT 'ledger_members表ID',
  `can_add` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '添加账目: 0-不允许, 1-全部',
  `can_edit` tinyint unsigned NOT NULL DEFAULT '2' COMMENT '修改账目: 0-不允许, 1-全部, 2-仅自己',
  `can_delete` tinyint unsigned NOT NULL DEFAULT '2' COMMENT '删除账目: 0-不允许, 1-全部, 2-仅自己',
  `can_reimburse` tinyint unsigned NOT NULL DEFAULT '2' COMMENT '修改报销状态: 0-不允许, 1-全部, 2-仅自己',
  `can_export` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '导出报表: 0-不允许, 1-全部',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  UNIQUE KEY `uk_ledger_member` (`ledger_id`, `member_id`),
  KEY `idx_ledger_id` (`ledger_id`),
  KEY `idx_member_id` (`member_id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='成员权限表';
```

**字段说明**:
- `member_id`: 关联`ledger_members.id`（不是user_id，因为一个用户可能在多个账本中有不同权限）
- `can_add`: 添加账目权限，0=不允许，1=全部
- `can_edit`: 修改账目权限，0=不允许，1=全部，2=仅自己创建的
- `can_delete`: 删除账目权限，0=不允许，1=全部，2=仅自己创建的
- `can_reimburse`: 修改报销状态权限，0=不允许，1=全部，2=仅自己创建的
- `can_export`: 导出报表权限，0=不允许，1=全部

**权限默认值**:
- 新成员加入时自动创建权限记录，默认值：can_add=1, can_edit=2, can_delete=2, can_reimburse=2, can_export=1
- 管理员角色：can_reimburse 默认为 0（不允许），需显式授权
- 创建者角色：不使用此表，直接拥有所有权限

**权限校验逻辑**（后端中间件）:
```
1. 查询当前用户在账本中的角色
2. 如果是创建者(role=1) → 放行所有操作
3. 如果是管理员(role=2)或成员(role=3) → 查询ledger_permissions表
4. 根据操作类型检查对应权限字段
5. 如果权限值为2(仅自己) → 还需检查当前用户是否为账目的创建者(user_id)
6. 如果账本已锁定(is_locked=1) → 拒绝所有写操作（添加/修改/删除/修改报销状态）
```

### 3.5 virtual_members - 虚拟成员表

```sql
CREATE TABLE `virtual_members` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '虚拟成员ID',
  `ledger_id` bigint unsigned NOT NULL COMMENT '账本ID',
  `name` varchar(50) NOT NULL COMMENT '名称',
  `avatar` varchar(255) DEFAULT NULL COMMENT '头像URL',
  `created_by` bigint unsigned NOT NULL COMMENT '创建人ID',
  `status` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '状态: 0-已删除, 1-正常',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_ledger_id` (`ledger_id`),
  KEY `idx_created_by` (`created_by`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='虚拟成员表';
```

**字段说明**:
- `ledger_id`: 所属账本，虚拟成员仅在所属账本内可见
- `name`: 虚拟成员名称（如"王总"、"李经理"、"客户A"）
- `avatar`: 头像URL，可从预设头像中选择或自定义上传
- `created_by`: 创建该虚拟成员的用户ID
- 虚拟成员不登录系统，仅作为记账时的收支人选项

**使用方式**:
- 记账时，收支人下拉列表 = 真实成员(ledger_members) + 虚拟成员(virtual_members)
- transactions表的`reimburse_user_id`字段需要区分真实成员和虚拟成员
  - 真实成员：`reimburse_user_id` > 0，`is_virtual = 0`
  - 虚拟成员：`reimburse_user_id` > 0，`is_virtual = 1`

### 3.7 transactions - 账目表

```sql
CREATE TABLE `transactions` (
  `id` bigint unsigned NOT NULL AUTO_INCREMENT COMMENT '账目ID',
  `ledger_id` bigint unsigned NOT NULL COMMENT '账本ID',
  `user_id` bigint unsigned NOT NULL COMMENT '记录人ID',
  `category_id` bigint unsigned NOT NULL COMMENT '分类ID',
  `amount` decimal(12,2) NOT NULL COMMENT '金额',
  `type` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '类型: 1-支出, 2-收入',
  `transaction_date` date NOT NULL COMMENT '交易日期',
  `remark` varchar(500) DEFAULT NULL COMMENT '备注',
  `payee_id` bigint unsigned DEFAULT NULL COMMENT '收支人ID（真实成员user_id或虚拟成员virtual_members.id）',
  `is_virtual_payee` tinyint unsigned NOT NULL DEFAULT '0' COMMENT '收支人是否为虚拟成员: 0-否, 1-是',
  `reimburse_status` tinyint unsigned NOT NULL DEFAULT '0' COMMENT '报销状态: 0-不适用, 1-未报销, 2-已报销',
  `reimbursed_at` datetime DEFAULT NULL COMMENT '报销时间',
  `reimbursed_by` bigint unsigned DEFAULT NULL COMMENT '操作报销的用户ID',
  `status` tinyint unsigned NOT NULL DEFAULT '1' COMMENT '状态: 0-已删除, 1-正常',
  `created_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '创建时间',
  `updated_at` datetime NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP COMMENT '更新时间',
  PRIMARY KEY (`id`),
  KEY `idx_ledger_id` (`ledger_id`),
  KEY `idx_user_id` (`user_id`),
  KEY `idx_category_id` (`category_id`),
  KEY `idx_transaction_date` (`transaction_date`),
  KEY `idx_reimburse_status` (`reimburse_status`),
  KEY `idx_payee` (`payee_id`, `is_virtual_payee`),
  KEY `idx_created_at` (`created_at`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='账目表';
```

**字段说明**:
- `user_id`: 记录这条账目的人（操作人）
- `payee_id`: 收支人ID，关联users.id或virtual_members.id
- `is_virtual_payee`: 标记收支人是否为虚拟成员，0=真实成员，1=虚拟成员
- `reimburse_status`: 0=非报销账本或不适用，1=未报销，2=已报销
- `reimbursed_at`: 标记已报销的时间
- `reimbursed_by`: 谁操作的报销状态变更

**收支人查询逻辑**:
```sql
-- 查询账目及其收支人信息
SELECT 
  t.*,
  CASE 
    WHEN t.is_virtual_payee = 0 THEN u.nickname 
    ELSE v.name 
  END AS payee_name,
  CASE 
    WHEN t.is_virtual_payee = 0 THEN u.avatar 
    ELSE v.avatar 
  END AS payee_avatar
FROM transactions t
LEFT JOIN users u ON t.payee_id = u.id AND t.is_virtual_payee = 0
LEFT JOIN virtual_members v ON t.payee_id = v.id AND t.is_virtual_payee = 1
WHERE t.ledger_id = ? AND t.status = 1;
```

## 5. 索引设计说明

### 5.1 索引策略

1. **主键索引**: 所有表使用自增ID作为主键
2. **唯一索引**: 用于保证业务唯一性（如邀请码、用户openid、成员权限唯一性）
3. **普通索引**: 用于频繁查询的字段（如外键、时间字段、状态字段）
4. **联合索引**: 用于多条件查询场景（如收支人查询：payee_id + is_virtual_payee）

### 5.2 关键查询场景索引

| 场景 | 索引 |
|-----|------|
| 查询用户账本列表 | ledger_members.user_id |
| 查询账本成员 | ledger_members.ledger_id |
| 查询成员权限 | ledger_permissions.ledger_id + member_id |
| 查询虚拟成员 | virtual_members.ledger_id |
| 查询账本账目列表 | transactions.ledger_id + transaction_date |

## 6. 数据安全与备份

### 6.1 软删除设计
- 所有业务表都有`status`字段
- 删除操作改为更新status=0
- 保留数据便于追溯和恢复

### 6.2 权限安全
- 所有写操作在后端中间件层强制校验权限
- 权限校验顺序：账本锁定检查 → 角色检查 → 权限字段检查 → 数据归属检查
- 创建者角色绕过权限表，直接放行

### 6.3 数据备份建议
- 每日全量备份
- 开启binlog增量备份
- 备份保留30天

## 7. 性能优化建议

### 7.1 分页查询
- 所有列表接口必须分页
- 默认每页20条，最大100条

### 7.2 统计查询优化
- 大额统计使用缓存（Redis）
- 定时任务预计算常用统计数据

### 7.3 图片存储
- 使用对象存储（OSS/COS）
- 图片URL使用CDN加速
- 定期清理已删除账目的图片

### 7.4 自动锁定定时任务
- 使用node-cron每分钟执行一次
- 批量查询`auto_lock_at <= now() AND is_locked = 0`的账本
- 批量更新锁定状态，减少数据库操作次数
